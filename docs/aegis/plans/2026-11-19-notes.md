# Cell notes

- Date: 2026-11-19
- Status: Implemented — reviewed
- Branch: `deku-biff`
- Depends on: `2026-11-19-header-footer-images.md`

## Goal

Close the basic cell-note gap:

- `Note::new(text)`, `set_author`, `set_visible`, `set_width`, `set_height`.
- `Worksheet::insert_note(row, col, &Note)`.
- `Worksheet::show_all_notes()` and `Worksheet::set_default_note_author(name)`.
- A binary `xl/commentsN.bin` part with authors and rich-text comments.
- A per-sheet VML note drawing linked with `BrtLegacyDrawing`.
- Comments content type and worksheet relationships.

Author-prefix rich text, note background colors, object movement, alt text, and
threaded comments stay out of scope.

## Aegis Visibility

This adds one public builder, three worksheet methods, a notes map, four core
record types, three scope marker pairs, one binary part per note-bearing sheet,
one VML part and relationship per note-bearing sheet, one worksheet
relationship, one content-type override, and one worksheet record.

The package already owns VML generation for header/footer images. Notes use a
separate VML part, matching the reference writer: one part for note shapes and
one for header/footer image shapes.

## Baseline / Authority

- [MS-XLSB] Comments part content type is
  `application/vnd.ms-excel.comments`; source relationship type is
  `http://schemas.openxmlformats.org/officeDocument/2006/relationships/comments`.
- Comments ABNF:
  `BrtBeginComments COMMENTAUTHORS COMMENTLIST *FRT BrtEndComments`,
  `COMMENTAUTHORS = BrtBeginCommentAuthors *BrtCommentAuthor BrtEndCommentAuthors`,
  `COMMENTLIST = BrtBeginCommentList *COMMENT BrtEndCommentList`,
  `COMMENT = [ACUID] BrtBeginComment [BrtCommentText] BrtEndComment`.
- `BrtBeginComment` is `iauthor: u32`, `rfx: UncheckedRfX` with equal first/last
  row and column, and a 16-byte GUID. The GUID is ignored for non-shared
  workbooks.
- `BrtCommentText.text` is a `RichStr` with `fRichStr = 1`.
- `BrtCommentAuthor.author` is an `XLWideString` of 1..=54 code units.
- `BrtLegacyDrawing.stRelId` is a `RelID`.
- Note VML uses the `_x0000_t202` shapetype, `x:ClientData ObjectType="Note"`,
  the target cell in `x:Row`/`x:Column`, `x:Anchor`, and an optional
  `x:Visible`.
- VML parts reserve 1024 shape ids per `o:idmap` block. A sheet with more than
  1024 notes advertises multiple comma-separated block ids and continues shape
  ids across them; later note sheets start after the consumed blocks.
- Notes use the reference default start-cell offsets: 15 or 49 pixels on the
  x axis and 2, 10, 16, 16, or 14 pixels on the y axis, with edge clamping.
- `rust_xlsxwriter` v0.102.0 defaults notes to 128x74 pixels and 128 notes per
  sheet; VML note parts are numbered separately from header/footer VML parts.

## Compatibility Boundary

- `Note` mirrors the reference builder names for text, author, visibility, and
  dimensions. It does not expose author-prefix or color setters in this slice.
- `insert_note` replaces an existing note at the same cell.
- The default author is the worksheet default, then `Author`.
- `show_all_notes` only overrides notes whose visibility was not set explicitly.
- Text is limited to 32,767 UTF-16 code units. Authors are limited to 52.
- Zero width/height setters are ignored.
- Notes and header/footer images use separate VML parts and separate worksheet
  relationships. Both records retain their ABNF positions:
  `BrtDrawing`, `BrtLegacyDrawing`, `BrtLegacyDrawingHF`, `BrtBkHim`.
- Plain text is emitted as one rich run at offset 0. The comment author is stored
  in the authors table, not prefixed into the text.
- No threaded comments, VML buttons, shapes, or note formatting.

## Change Necessity

The writer has no comments part, note records, VML note shape, or legacy drawing
record. A note cannot be represented by the existing worksheet records or
header/footer VML path.

## Review

`NoteReview` found one P2 and one P3, both fixed.

- P2: note VML advertised one 1024-id block and later sheets reused consumed
  blocks. `note_vml_blocks` now emits comma-separated ids, shape ids continue
  across blocks, and the package advances the note data id by the block count.
- P3: note anchors dropped the reference start offsets and edge clamping.
  `note_start_col`/`note_start_row` now use the 15/49 px and 2/10/16/16/14 px
  offsets, with hidden-cell adjustment. A B2 test asserts `2,15,0,10`.
- P3 follow-up: edge special cases were off by one because the reference uses
  counts, not max indexes. The last three columns/rows now map to the reference
  start cells, and a last-row/last-column test asserts
  `16380,49,1048571,14`. The reviewer confirmed no remaining findings.
