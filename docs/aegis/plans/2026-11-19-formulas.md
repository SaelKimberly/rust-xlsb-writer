# Scalar formulas

- Status: Implemented — reviewed
- Date: 2026-11-19
- Scope: `Formula`, `Worksheet::{write_formula, write_formula_with_format,
  set_formula_result, set_formula_result_default}`, scalar formula token
  encoding, cached result records, and automatic recalculation on load.
- Gap source: `docs/gap-analysis-rust-xlsxwriter.md` §3.2, §5, and P0b.
- Reference: vendored `rust_xlsxwriter` v0.102.0 `formula.rs` and
  `worksheet.rs`.
- Spec: MS-XLSB §2.4.684-2.4.687, §2.5.98.4, and Ptg sections
  §2.5.98.16-98.91.
- Baseline: `8309c27 feat: add Excel 2023 theme support`.

## Goal

Add the source-compatible scalar formula API:

```rust
let mut workbook = Workbook::new();
let worksheet = workbook.add_worksheet();
worksheet.write_formula(0, 0, "=1+2")?;
worksheet.write_formula(1, 0, Formula::new("=A1*2").set_result("6"))?;
worksheet.set_formula_result(0, 0, "3");
worksheet.set_formula_result_default("");
workbook.save("formulas.xlsb")?;
```

A formula is parsed when it is written, so syntax errors are reported without
waiting for save. Cached results are written using the matching
`BrtFmlaNum`/`BrtFmlaString`/`BrtFmlaBool`/`BrtFmlaError` record. A workbook
with formulas emits `BrtCalcProp` with `fFullCalcOnLoad` when the caller has
not selected a calculation mode.

Out of scope: array and dynamic-array formulas, shared formulas, table
formulas, data-table formulas, external-workbook references, cross-sheet
references, user-defined names inside formulas, and future/dynamic functions.
These return `Error::FormulaError` instead of producing a partial token
stream.

## Aegis Visibility

The formula token stream is a durable wire contract. A malformed stream makes
Excel reject or repair the file, and a wrong cached-result record changes what
non-calculating readers display. The parser must therefore reject unsupported
syntax instead of guessing, and the cached value must select the record type
that matches its value.

The public API is also a compatibility contract. `Formula::new` accepts the
same optional leading `=` and array braces as the reference; formula strings
remain US-English syntax with comma separators.

## Architecture

`rust-xlsb-core`:

- Add `prelude/record/brt_fmla.rs` with `CellParsedFormula` and the four cell
  formula records.
- `CellParsedFormula` contains `cce`, `rgce`, `cb`, and `rgcb`; `Checked`
  enforces `1..=16384` token bytes and exact lengths.
- Records use the existing `Cell`, `Xnum`, `BErr`, and `XlWideString` types.
- Re-export and register every new record in the `test_biff_export` table.

`rust-xlsb-writer`:

- Add `formula.rs` with:
  - the public `Formula` type and its `IntoExcelData` implementations;
  - a recursive-descent parser that emits reverse-polish Ptg tokens directly,
    without an AST;
  - a fixed function table for classic Ftab ids and arities;
  - cached-result parsing that matches the reference result-type rules.
- `CellData` gains a formula variant containing the token stream and resolved
  cached result.
- `Worksheet` gains the four public methods plus formula-result defaults.
- `sheet.rs` writes the result-specific formula record.
- `package.rs` emits `BrtCalcProp` only when formulas exist and no calculation
  mode was explicitly set.

`rust_xlsb_core` remains the only owner of record framing. `rust-xlsb-writer`
remains the only owner of formula parsing and API behavior.

## Formula Subset

The parser accepts:

- decimal numbers, including an exponent;
- quoted strings with Excel `""` escaping;
- `TRUE` and `FALSE`;
- error literals `#NULL!`, `#DIV/0!`, `#VALUE!`, `#REF!`, `#NAME?`, `#NUM!`,
  `#N/A`, and `#GETTING_DATA`;
- A1 cell references and `A1:B2` ranges, with `$` absolute markers;
- unary `+`, unary `-`, `%`, `+`, `-`, `*`, `/`, `^`, `&`, and the six
  comparison operators;
- parentheses;
- the classic worksheet functions listed in the implementation table:
  arithmetic, aggregation, logical, text, date, lookup, and information
  functions.

References are same-sheet only. Identifiers followed by `!` and identifiers
that are not a known function or boolean return `Error::FormulaError`.

## Token Encoding

- `PtgInt` for non-negative integers up to 65535; `PtgNum` otherwise.
- `PtgStr` for strings of at most 255 UTF-16 code units.
- `PtgRef` and `PtgArea` with value-class bytes `0x44`/`0x45` and relative
  flags in the column words.
- Fixed-arity functions use `PtgFunc`; optional/variable-arity functions use
  `PtgFuncVar` with the actual argument count.
- Operators and unary/postfix operators use their one-byte Ptg values.
- Missing function arguments use `PtgMissArg`.

## Cached Results

`Formula` has no explicit result by default. The worksheet default result is
`"0"`, matching the reference. At write time:

- parse the result as `f64` when possible;
- otherwise use `TRUE`/`FALSE` for booleans;
- otherwise use the matching `BErr` for the seven Excel error strings;
- otherwise store a string result.

`set_formula_result` replaces the cached result of an existing formula and is
a no-op for non-formula cells, matching the reference's permissive behavior.
`set_formula_result_default` applies to formulas written afterward.

## Tests

Core:

- `CellParsedFormula` and all four formula records round-trip through deku.
- Invalid `cce` and mismatched token lengths are rejected.

Writer:

- token tests for cell references, ranges, integers, strings, parentheses,
  operators, functions, unary/postfix operators, and errors;
- parser rejection tests for unknown functions, wrong arity, cross-sheet
  references, named ranges, malformed strings, out-of-range references,
  excessive nesting, and oversized formulas;
- result inference tests for number, boolean, error, string, and the
  worksheet default;
- `set_formula_result` mutates only formula cells and rejects oversized
  string results at save.

End to end and package:

- calamine reads cached numbers, strings, and booleans; it exposes cached
  error formulas as empty cells, so error records are proven by package tests;
- the worksheet contains the matching formula records;
- `BrtCalcProp` appears with formulas and stays absent for formula-free
  workbooks;
- an explicit calculation mode is not overwritten;
- LibreOffice opens the generated workbook without repair, preserves
  parenthesized formula text, and recalculates to the expected values.

## Review

`FormulaReview` found one blocking defect and two non-blocking issues:

1. Parenthesized groups emitted no `PtgParen`, so token consumers and
   LibreOffice reconstructed the wrong formula. Fixed by emitting `0x15`
   after the closing parenthesis and adding a token regression test.
2. `set_formula_result` bypassed the cached-string length guard. Fixed by
   rejecting oversized `BrtFmlaString` results during sheet serialization.
3. The depth guard charged two frames for each parenthesis and unary chain.
   Fixed with separate expression and unary depth counters, plus nesting
   regression tests.

The reviewer also requested payload round-trip, parenthesized-expression,
255/256-character string, oversized-formula, non-formula result, and
oversized-result tests; all were added. It independently verified record
framing, Ptg layouts, all 116 function-table entries through LibreOffice,
precedence, calc-prop placement, and the calamine formula-error reader gap.
The `MAX_FUNCTION_ARGS` concern was addressed by allowing the full 255
arguments through `PtgFuncVar`.

## Risks

- XLSB stores token streams, not formula text; every supported construct needs
  its exact Ptg bytes.
- Excel accepts `PtgFunc` only for fixed-arity functions and `PtgFuncVar` for
  variable/optional functions. The function table must encode both correctly.
- Cross-sheet references need `BrtExternSheet` indexes and are deliberately
  rejected in this batch.
- Formula results are cached values, not calculations. The writer sets
  `fFullCalcOnLoad` when formulas are present so Excel recalculates them.
